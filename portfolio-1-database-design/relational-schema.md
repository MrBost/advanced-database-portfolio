# Relational schema and data dictionary

All tables are in schema `bookmania`. **PK** = primary key; **FK** = foreign key; **UQ** = unique. All fields are required unless marked nullable. Identity keys are generated by PostgreSQL.

| Table | Columns and types | Keys and main rules |
|---|---|---|
| category | category_id integer; name varchar(80) | PK category_id; UQ nonblank name |
| customer | customer_id integer; full_name varchar(120); email varchar(254); address_line varchar(200); city varchar(80); created_at timestamptz | PK customer_id; UQ lowercase email with basic format check; nonblank name/address/city |
| book | book_id integer; category_id integer; isbn varchar(13); title varchar(200); author_name varchar(120); unit_price numeric(10,2); stock_quantity integer | PK book_id; FK category_id -> category; UQ 13-digit isbn; nonblank title/author; price >= 0; stock >= 0 |
| customer_order | order_id integer; customer_id integer; ordered_at timestamptz; status varchar(15); delivery_address_line varchar(200); delivery_city varchar(80) | PK order_id; FK customer_id -> customer; status in pending/paid/shipped/delivered/cancelled; nonblank shipping snapshot |
| order_item | order_id integer; book_id integer; quantity integer; unit_price_at_purchase numeric(10,2) | Composite PK (order_id, book_id); both columns are FKs; quantity > 0; purchase price >= 0 |
| payment | payment_id integer; order_id integer; reference varchar(80); amount numeric(12,2); method varchar(20); paid_at timestamptz | PK payment_id; UQ FK order_id -> customer_order; UQ nonblank reference; amount > 0; method card/bank_transfer |
| delivery | delivery_id integer; order_id integer; tracking_number varchar(80); status varchar(15); dispatched_at timestamptz; delivered_at timestamptz **nullable** | PK delivery_id; UQ FK order_id -> customer_order; UQ nonblank tracking_number; dispatched requires null delivered_at; delivered requires delivered_at >= dispatched_at |

Prices are additionally bounded to exclude special non-finite numeric values. `created_at` and `ordered_at` default to the current timestamp; order status defaults to pending. PostgreSQL stores timestamptz as an instant; display depends on the session time zone. Seed inputs explicitly use UTC+01:00.

## Relationships

- Category 1 -> 0..many Book; each book requires exactly one category.
- Customer 1 -> 0..many CustomerOrder; each order requires exactly one customer.
- CustomerOrder 1 -> 0..many OrderItem at table-constraint level; business minimum is one after order creation completes.
- Book 1 -> 0..many OrderItem; each line requires exactly one book.
- CustomerOrder 1 -> 0..1 Payment; each payment belongs to exactly one order.
- CustomerOrder 1 -> 0..1 Delivery; each delivery belongs to exactly one order.

All foreign keys use PostgreSQL's default NO ACTION on update/delete. Primary and unique constraints create indexes automatically. Extra query-oriented indexes will be evaluated in Portfolio 2 rather than added without measurements.

`order_total` is a view, not an eighth table. It calculates `SUM(quantity * unit_price_at_purchase)` per order. It has no row for an empty order; empty orders are an unfinished/invalid business state to be controlled by order-creation logic.
